# DentAll 商城项目总计划（单休·编辑先行版）

## 1. 当前结论

- 工作制度：16周，每周工作6天、休息1天，共96个工作日。
- 对外周期：约4个月；这是范围和依赖基本稳定时的计划基线，不是无条件承诺。
- 第一阶段业务目标：先让网站编辑人员在受保护的Staging后台安全录入商品、文章、页面、图片和SEO信息。
- 第一周不会公开正式商城；D6交付的是受保护、禁止索引、不可使用真实支付的编辑试录环境。
- 商品批量录入从D12字段冻结后开始；文章和页面批量录入从D18流程验收后开始。
- 首页和前端视觉后移到W4以后，编辑人员可以与开发并行工作。

## 2. 大方向与优先级

| 优先级 | 工作方向 | 业务结果 |
|---|---|---|
| P0 | 编辑内容生产线 | 编辑无需开发介入即可录入标准商品、文章、页面、图片和SEO字段 |
| P1 | 商品浏览与交易闭环 | 访客可以查找商品并完成测试下单 |
| P1 | 数据、权限与SEO稳定 | 字段、URL、媒体和发布权限不会因后续开发频繁推翻 |
| P2 | 四端UI还原 | 手机、平板横竖屏和PC达到确认稿结构与主要视觉效果 |
| P2 | 性能、安全、备份和上线 | 商城可恢复、可回滚、可监控地部署到生产 |
| P3 | 高级筛选、动效和增强内容 | 有余量再做，不能挤占交易测试和上线缓冲 |

### 编辑先行的技术原则

1. 商品直接使用WooCommerce原生`Product`，不创建商品CPT。
2. 文章使用WordPress原生`Post`，About、政策等使用原生`Page`。
3. 商品分类使用Product Categories；可筛选规格使用全局Attributes；影响价格、SKU或库存的选项使用Variations。
4. 先用5～10个代表商品验证原生字段，只有原生能力确实不足时才增加ACF。
5. Solutions条目少时先用Page；只有大量条目且需要独立归档、详情或筛选时才考虑CPT。
6. 编辑只获得完成内容工作的最小权限，不授予插件、主题、系统配置和生产部署权限。

## 3. 工时基线

- 标准工作日：8小时在岗。
- 日内节奏：7个“50分钟专注 + 10分钟休息”周期，最后1小时用于复盘、验证证据、Git整理和Obsidian笔记。
- 每日开发/测试：350分钟，约5小时50分钟。
- 每日总结与计划：60分钟。
- 每日有效投入：6小时50分钟。
- 每周有效投入：41小时。
- 96日总在岗：768小时。
- 96日开发/测试：约560小时。
- 96日复盘、记录和计划：96小时。
- 总有效工作：约656小时。
- 估算波动：范围清晰时约±20%；设计、支付、物流、数据迁移或反馈不确定时可能增加40%以上。

## 7. 编辑并行录入规则

### D1-D6：只允许试录

- 只录测试商品和测试文章，不能大批量复制真实数据。
- 编辑先保存草稿，不直接发布。
- 开发记录所有卡点，但不为个别人的习惯立即堆叠ACF或自定义后台。

### D7-D12：商品代表样本验证

- 选择5～10个覆盖面最大的商品：简单商品、可变商品、促销、缺货、多图、资料下载。
- D12验收前不导入全部商品。
- D12后核心字段变化视为数据迁移和范围变更。

### D13-D18：内容代表样本验证

- 使用3篇不同长度的文章和1个固定页面验证标题、摘要、正文、特色图、内链、SEO和发布流程。
- D18后编辑可持续录入，但上线前仍需抽样审核。
- 编辑不能自行改变Slug规则、分类层级、字段结构和固定链接。

### D19-D96：开发与编辑并行

- 编辑在Staging录入真实内容，开发以真实数据验证前端模板。
- 每周第6天集中处理编辑反馈，P0/P1立即处理，纯便利性优化进入Backlog。
- 前端模板尚未完成时，后台预览不代表最终视觉效果。

## 8. 范围边界与压缩规则

第一版必须包含：编辑商品与文章流程、四端核心商城模板、标准商品与变体、搜索和基础筛选、购物车、结账、账户、标准支付物流插件、邮件、基础SEO、缓存、性能、安全、测试和上线。

默认不包含：ERP/CRM深度同步、多仓库、复杂批发价、多级会员、自研支付网关、复杂税务、未经确认的多语言、大规模历史数据清洗和无限修改轮次。

如果16周出现偏差，按以下顺序延后到v1.1：

1. 高级组合筛选和复杂品牌归档。
2. Solutions独立CPT和增强内容关系。
3. 商品FAQ增强、相关商品高级规则和非核心动效。
4. 对象缓存/CDN进阶调优。

不能压缩：权限、备份恢复、支付金额、库存、订单、邮件、缓存会话、SEO索引和上线回归。

## 9. 关键依赖与风险

- W1需要可供编辑访问的Staging。如果云服务器或临时测试环境未提供，编辑只能在开发者本机旁操作，M1会被阻塞。
- 编辑、SEO和商城管理员必须明确为不同权限，不共用管理员账户。
- 商品字段在D12后推翻会产生批量迁移和返工；文章分类及URL在D18后推翻会产生SEO风险。
- 支付账户、物流国家、运费、税费和SMTP最晚应在W9前确认。
- 单休提高疲劳风险：每天最多7个专注周期，第7天完整休息，不允许连续数周取消休息日。
- 设计素材可以后补，但结构、比例和字段变化必须登记需求变更。
