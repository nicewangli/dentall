# DentAll 商城项目总计划（双休版）

## 1. 推荐结论

双休版推荐采用 **20周 × 每周5天 = 100个工作日**，对应约4.5～5个月自然时间。它保留单休版的第一版完整范围，并增加4个缓冲工作日，用于联调、验收和上线观察。

不建议把同样范围压进16周双休：16周只有80个工作日，比原96日计划少16天，缺少约109小时有效工作，只能通过砍范围或长期加班弥补。

## 2. 工时基线

- 工作制度：周一至周五工作，周六、周日休息；实际休息日可调整，但必须保证每7天有2个完整休息日。
- 标准工作日：8小时在岗。
- 日内节奏：7个“50分钟专注 + 10分钟休息”周期，最后1小时复盘和Obsidian笔记。
- 每日有效投入：开发/测试350分钟 + 总结60分钟 = 6小时50分钟。
- 每周有效投入：34小时10分钟。
- 100日总在岗：800小时。
- 100日开发/测试：约583小时20分钟。
- 100日复盘、记录和计划：100小时。
- 总有效工作：约683小时20分钟。
- 周期休息：约116小时40分钟，不计为有效工时，但属于保证质量的必要时间。

## 3. 每日固定开发周期

| 周期 | 任务类型 | 时长 |
|---|---|---:|
| C1 | 当天最难、最高风险任务 | 50分钟 |
| C2 | 核心任务继续或技术验证 | 50分钟 |
| C3 | 主体实现 | 50分钟 |
| C4 | 主体实现 | 50分钟 |
| C5 | 联调、响应式或后台体验 | 50分钟 |
| C6 | 自动化/手工测试 | 50分钟 |
| C7 | 修复、整理、提交和验收证据 | 50分钟 |
| 最后1小时 | 复盘、计划偏差、Obsidian笔记 | 60分钟 |

以下每个工作日均为6小时50分钟有效投入。`C1-C2`、`C3-C5`、`C6-C7`分别是100、150、100分钟，最后1小时固定复盘。

## 7. 疲劳与质量规则

- 周末不安排常规开发，不把延期自动转成周末加班。
- 只有生产故障或已经确认的上线窗口才临时占用周末，并在下一周补休。
- 每天最多7个专注周期；连续两个周期卡住同一问题，应切换到诊断、记录假设或向Codex求助。
- 周五C6-C7优先回归、清理和提交，避免周末前留下不可恢复的半完成状态。
- 每周至少保留半天给测试、文档和计划校准，减少“功能写完但无法上线”的风险。
- 实际进度落后超过2个工作日，应调整范围或里程碑，而不是连续加班。

## 8. 范围边界

第一版包含：核心商城模板、四端响应式、标准商品与变体、搜索筛选、购物车、结账、账户、标准支付物流插件、邮件、内容页、基础SEO、缓存、性能、安全、测试和上线。

页面结构、商品字段、URL、支付物流、第三方接口或批量迁移发生变化时，必须重新估时。
