# 项目背景与边界

## 项目概述

- 项目名称：DentAll 独立站商城重建。
- 技术方向：WordPress + WooCommerce。
- 开发模式：单人全栈开发，编辑/SEO人员并行录入商品和内容。
- 当前排期：单休20周编辑先行版，每周6天、120个工作日，自然周期约4.6个月，对外按4.5～5个月管理。
- 视觉目标：按已确认的PC、平板横屏、平板竖屏和手机效果图实现响应式页面。
- 核心目标：企业掌握源码、数据库、服务器、域名和第三方账户控制权。
- 第一版语言与币种：英语、美元；代码保留国际化和币种扩展边界，但第一版不实现多语言或多币种功能。
- 项目性质：从零开发的新站，不存在旧站，也不包含旧站URL、内容或数据库迁移。

## 业务目标

1. 用户可以发现、筛选、查看并购买牙科相关商品。
2. 编辑人员可以在后台独立维护商品、分类、图片、内容和SEO信息。
3. 商城具备可测试、可备份、可回滚和可持续维护的上线基础。
4. 第一版优先完成稳定交易闭环，不追求无限定制。
5. 前25个工作日优先建立商品、文章、页面、媒体和SEO内容生产线，让编辑与后续前端开发并行。

## 用户角色

| 角色 | 主要任务 | 权限原则 |
|---|---|---|
| 访客 | 浏览、搜索、筛选、下单 | 只访问公开内容 |
| 客户 | 管理地址、订单和账户 | 只能访问自己的数据 |
| 编辑/SEO | 录入商品、内容和SEO | 不授予插件、主题和系统管理权限 |
| 商城管理员 | 处理商品、订单、优惠和客户 | 按业务需要授权 |
| 开发者 | 配置、开发、测试和部署 | 生产变更需按发布清单执行 |

## 老板参与边界

- 老板不参与日常项目执行、技术配置、测试、内容录入或开发验收操作。
- 老板只负责提供项目资金、域名及必要访问资料，以及实体产品、商品资料和其他业务内容支持。
- 服务器购买、域名选择或第三方账户开通需要老板出资或提供资料时，由开发者提出明确清单；具体配置和验证由开发者执行。
- 日常进度、技术决策和质量验收由开发者按项目文档推进；需要业务事实时向编辑人员或相应内容提供者收集。

## Codex教学模式

- 默认不主动教学，以项目推进、结论、风险和验证证据为主。
- 开发者明确表示不懂或主动追问知识时，Codex切换到详细教学模式。
- 教学采用“记忆宫殿定位 → 实体比喻建模 → 对应真实技术概念 → 后台/代码实际路径 → 验证与常见错误”的顺序。
- 教学结束后回到当前项目任务，不把讲解自动扩展成未授权的配置或代码修改。

## 第一版范围

- 全局页头、导航、搜索、页脚和Newsletter。
- 首页四端响应式。
- 商品分类、列表、搜索、排序、分页和第一版筛选。
- 商品详情、图库、简单商品、变体、库存和相关商品。
- 购物车、优惠券、运费摘要、结账、支付沙盒、订单邮件。
- 登录、注册、密码重置、地址和订单中心。
- About、Contact、政策、FAQ、404、博客和Solutions最小版本。
- 基础SEO、Schema、站点地图、Canonical和重定向策略。
- 缓存、图片优化、安全、备份、测试、部署和交接。

## 默认不包含

- ERP/CRM深度同步、多仓库和复杂库存系统。
- 复杂批发价、多级会员和按客户分级定价。
- 自研支付网关或复杂税务系统。
- 第一版多语言和多币种业务逻辑；后续启用时另行评估。
- 历史站点迁移、大规模历史数据清洗和无限修改轮次。
- 第一版不必要的复杂动画及内容管理平台化。

## 已确认原则

- 商品使用WooCommerce原生`product`，不重复创建商品CPT。
- 可筛选规格使用全局属性；影响价格或库存的规格使用变体。
- ACF只补充原生字段无法表达的展示字段。
- 使用子主题、模板覆盖、hooks和filters，不修改核心文件。
- 图片素材可以后补，但组件结构、字段和图片比例需要提前冻结。
- 第一周开放的是受保护且禁止索引的Staging，不是正式公开商城。
- D6开始安全试录；D18形成商品模型候选冻结；D24完成内容样本；D25综合验收后开放商品、文章和页面批量录入。

## 项目成功标准

- 编辑人员无需开发介入即可录入标准商品。
- 用户可以在Staging完成从浏览到测试支付的完整流程。
- 四端关键页面无阻塞性布局问题。
- 核心交易、权限、SEO、缓存和备份测试通过。
- 正式上线具备明确备份、回滚、监控和交接证据。
