# 商品与内容数据字典

## 字段选择规则

1. WooCommerce原生字段能表达的，不增加ACF。
2. 用户需要筛选的规格，使用全局商品属性。
3. 影响价格、SKU或库存的选择，使用商品变体。
4. 只用于结构化展示且原生字段不足的内容，才使用ACF。
5. 普通介绍放详细描述；简要卖点放简短描述。

## 数据来源与TEST规则

- 商品数据应标记为`已确认`、`来源值待确认`、`TEST`或`缺失`；只有`已确认`可以作为正式发布数据。
- 仓库分类、内部编号和内部单价只能作为建模输入，不能自动转成网站分类、公开SKU或正式USD售价。
- 未确认的价格、库存、重量、尺寸和变体组合可用TEST数据验证流程，但商品名称、SKU及相关记录必须包含明确的`TEST`标识。
- TEST数据仅限Local或受保护、`noindex`且未启用真实支付的Staging；D25开放批量录入前必须清理或替换。
- 医疗/合规事实、认证结论和素材公开授权不得使用推测或TEST值代替业务确认。
- D18冻结商品模型和编辑流程候选，不代表全部正式商品资料完成；约970条仓库物料的全量清洗与录入不属于W2～W3。

## SKU规则v1候选

### 标识职责

- 网站SKU是WooCommerce商品及变体的公开、稳定业务标识，不等同于数据库ID、商品Slug、仓库库位、内部编号或临时文件名。
- 来源优先级为：业务确认可公开且稳定的制造商货号 → DentAll分配的网站商品编号 → 明确带`TEST-`前缀的测试编号。
- 仓库内部编号和供应商货号必须分别保留来源含义；未经业务确认，均不得自动发布为网站SKU。
- 分类名称、促销状态、价格、库存状态等会变化的信息不得编码进SKU，避免分类调整或促销结束后被迫改号。

### 格式与唯一性

- 正式SKU候选仅使用大写英文字母`A-Z`、数字`0-9`和短横线`-`，不使用空格、中文、斜杠、货币符号或营销文案。
- SKU在全站所有商品和变体之间唯一；大小写不同不能用来表达两个不同商品。
- SKU发布后原则上不修改。确需修改时，必须检查订单历史、库存/采购对照、CSV导入导出和外部系统引用，并保留旧新映射。
- SKU不承担SEO职责；商品名称和Slug按各自规则维护。

### 主商品、变体与TEST数据

- 简单商品使用一个独立SKU。
- 可变商品保留父商品SKU；每个可售变体另有唯一SKU。变体后缀只使用已确认、稳定且有映射表的属性值代码。
- 不直接把未经规范化的属性显示名拼进SKU；显示名改写时，既有SKU不应随之自动变化。
- 未确认数据统一使用`TEST-`前缀，例如`TEST-DTL-ZR-0001`；示例只用于解释格式，不是正式编码方案。
- SKU采用混合来源：业务确认可公开且可靠的制造商货号优先；不合适或不存在时，由`DentAll Website Manager`按统一规则分配DentAll自有SKU。
- `DentAll Website Manager`负责日常创建、重复检查和维护商品及变体SKU，开发者不参与逐个编号。批量导入、批量改号、历史数据迁移或系统校验异常才升级给开发者。
- D12原型创建前仍需由业务方确认制造商货号是否允许公开，并形成DentAll自有SKU的最小编号规则。

## 品牌数据治理v1候选

- 品牌回答“谁生产或以谁的品牌销售”，不能复制为Product Category、产品用途或Solutions。
- 品牌名称使用业务确认的正式公开英文名；大小写、空格、标点和常见别名统一映射到一个规范名称，避免出现重复品牌项。
- 每个商品原则上只记录一个主要品牌。制造商、经销商、自有品牌和OEM关系如需同时展示，应先明确业务语义，不能创建多个近义品牌凑数。
- 无品牌商品、ADS自有品牌和第三方原厂品牌必须分别确认；不得用`Unknown`、供应商文件夹名或仓库分类充当正式品牌。
- 商城名称保持`DentAll`；`ADS`是商品品牌，两者不得在品牌字段、商品名称或前台标识中相互替代。
- D9只形成名称、来源、负责人和重复项治理规则候选；品牌字段载体、归档URL、筛选与索引方案留到D52冻结。
- 品牌正式实现确认前不自建品牌CPT、不安装品牌插件，也不使用普通商品标签长期代替品牌。

## 全局属性模型v1候选

以下只是候选，编辑录入代表商品后再冻结，禁止一次性创建大量无用属性。

| 后台英文名称候选 | Slug候选 | 是否筛选 | 是否可能做变体 | 示例与边界 |
|---|---|---:|---:|---|
| Material | `material` | 是 | 否/待确认 | Zirconia、PMMA、EVA；不重复建成分类 |
| Size | `size` | 是 | 是 | 必须带明确单位，例如`98 mm`；物流包装尺寸仍用Shipping字段 |
| Shade | `shade` | 视商品 | 是 | 牙科行业色号，例如`A2`；不与普通颜色混用 |
| Color | `color` | 视商品 | 是 | 普通可见颜色；不承载牙科色号 |
| Package Quantity | `package-quantity` | 是 | 是 | 表示可售包装内数量，例如`20 pcs`；不等同于库存数量 |
| Compatible System | `compatible-system` | 是 | 通常否 | 适配平台或系统；正式名称和术语待样本确认 |
| Compatible Device | `compatible-device` | 是 | 通常否 | 适配设备/手柄；若与System无法稳定区分则D12前合并评估 |
| Intended Use | `intended-use` | 待验证 | 通常否 | 仅在客户确实需要跨分类筛选时创建，不能复制Solutions或分类 |

### 属性选择与命名规则

- 同一含义且会被多个商品复用、用于筛选或形成购买选项时，才创建Global Attribute。
- 只属于单个商品且不需要筛选的普通参数优先使用商品级属性、描述或经验证的最小ACF字段，不污染全局属性库。
- 属性后台名称和Slug使用稳定英文；面向客户的显示文案未来使用可翻译输出，不把中英文同时写进同一个属性值。
- 属性项使用规范化显示值及单位，例如`98 mm`、`20 pcs`；不要同时创建`98mm`、`98 mm`和`98MM`。
- 尺寸、重量和数量必须区分测量对象：产品规格用属性，物流重量/包装尺寸用WooCommerce Shipping字段，库存数量用库存字段。
- `Shade`与`Color`分开维护；`Package Quantity`与库存数量分开维护；品牌、认证、分类和Solutions不混入属性项。
- 属性是否显示在前台、是否用于筛选、是否用于Variation是三个独立决定，不因创建了属性就默认全部启用。

## ACF最小候选字段

| 字段 | 类型 | 用途 | 是否进入第一版 |
|---|---|---|---|
| 技术参数组 | Repeater/Group | 有结构地展示参数名和值 | 待代表商品验证 |
| 认证信息 | Text/Repeater | 展示认证名称和编号 | 待确认 |
| 资料下载 | File/Repeater | PDF说明书、证书或目录 | Should |
| 使用说明 | WYSIWYG | 原生描述不便拆分时使用 | 待确认 |
| 交付周期 | Text | 定制类商品说明 | 待确认 |
| 商品FAQ | Repeater | 商品特有问答 | Could |

## 变体规则

- 只有会改变价格、SKU、库存、图片或购买选择的属性才设为变体。
- “可筛选”不等于“必须做变体”；Material或Compatible System可以参与筛选但不生成购买组合。
- 控制变体组合数量；组合过多时重新评估商品拆分方式。
- 每个可售变体必须检查价格、库存状态、SKU和默认选择。
- 不可购买组合必须有清晰提示，不能静默失败。
- D9只定义属性到Variation的映射条件；合法组合、父子SKU实例、价格和库存留到D10及D14验证。

## 内容类型

| 内容 | 推荐结构 | 说明 |
|---|---|---|
| 商品 | WooCommerce Product | 不创建重复CPT |
| 商品分类 | Product Category | 可维护层级和描述 |
| 品牌 | 官方能力或成熟插件 | 方案确认前不自建CPT |
| 博客 | WordPress Post | 使用分类管理主题 |
| About/政策 | WordPress Page | 共用内容页模板 |
| Solutions | Page或CPT待定 | 数量少用Page；大量且需归档再用CPT |
| 案例 | 暂不进入第一版 | 需求明确后再决定CPT |

## 文章与页面字段

| 字段 | 内容类型 | 必填 | 规则 |
|---|---|---:|---|
| 标题 | Post/Page | 是 | 清晰描述主题，避免堆砌关键词 |
| Slug | Post/Page | 是 | 小写英文和短横线；发布后未经SEO确认不得修改 |
| 摘要 | Post | 是 | 用于文章列表和分享摘要，避免直接截断正文 |
| 正文 | Post/Page | 是 | 使用统一标题层级；不粘贴外部内联样式 |
| 特色图 | Post | 是 | 按约定比例上传，并填写可理解的alt |
| 分类 | Post | 是 | 至少一个主分类；D25后不随意新增近义分类 |
| 标签 | Post | 否 | 有明确聚合价值才使用，避免一文一标签 |
| 作者 | Post | 是 | 使用真实或统一品牌作者账号 |
| SEO标题/描述 | Post/Page | 建议 | 使用SEO插件字段；上线前抽样检查 |
| 内部链接 | Post/Page | 建议 | 链接相关商品、分类或内容，禁止使用临时Staging绝对地址 |
| 发布状态 | Post/Page | 是 | 试录阶段保存草稿；按审核规则发布 |

## 编辑录入验收

- 第一批只录入5～10个代表商品，覆盖简单商品、变体、促销、缺货、多图和资料下载。
- D18商品模型候选冻结前不要批量导入全部商品。
- D24前先录入3篇不同长度文章和1个固定页面，验证摘要、特色图、内链、SEO和发布流程。
- D25综合验收后才开放批量录入；此后未经确认不得改变核心商品字段、文章分类结构、Slug规则和固定链接。
- 每次字段改变记录迁移影响、旧数据处理和新增工时。
