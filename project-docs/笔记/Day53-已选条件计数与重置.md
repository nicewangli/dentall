## 可复用核心思想

- 跨平台不变量：筛选UI、结果集合、已选状态、可撤销URL和每项计数必须来自同一查询合同；其中任一层使用不同语义，就会出现“看得见却清不掉”或“计数与结果不一致”。
- WordPress/WooCommerce实现：在Woo消费GET前规范主查询输入，复用主查询输出商品；分面计数只补齐Woo当前遗漏的其他维度，并沿用其缓存与父商品模型，避免另造商品真相源。
- 缓存原则：先用冷/暖同一请求证明查询上限与缓存命中，再讨论优化；查询数稳定不等于Production响应或Core Web Vitals已经通过。
- Shopify或其他平台：可迁移的是规范URL、可逆状态、facet自排除与其他维度约束；Shopify Search & Discovery、Storefront API或第三方应用的计数、缓存和URL机制尚未在DentAll验证，必须标记待验证。
