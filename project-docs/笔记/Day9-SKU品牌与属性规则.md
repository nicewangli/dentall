## SKU规则v1候选

### 来源顺序

1. 业务确认可公开且稳定的制造商货号。
2. 没有合适制造商货号时，由业务方按统一流程分配DentAll网站编号。
3. 未确认的原型只使用带`TEST-`前缀的测试编号。

仓库内部编号、供应商货号、文件名和网站SKU是四种可能不同的标识。仓库编号仅作内部对照，不能自动公开；供应商货号也必须确认公开许可、稳定性和唯一性后才能采用。

### 已确认的执行责任

- SKU采用混合来源：可公开且可靠的制造商货号优先；不适用时创建DentAll自有SKU。
- `DentAll Website Manager`可独立创建和维护父商品及变体SKU，并负责日常重复检查；不需要开发者逐个操作。
- 普通录入员可按后续权限测试结果填写候选SKU；正式SKU的业务准确性由Website Manager负责。
- 开发者负责规则、权限、系统校验和异常处理；批量导入、批量改号、历史迁移或校验故障才升级给开发者。
- WooCommerce原生唯一性检查作为最后防线，不能替代编辑人员按规则核对来源和格式。

### 格式和稳定性

- 使用大写英文字母、数字和短横线；不使用空格、中文、斜杠、货币符号或营销词。
- 全站商品和变体SKU唯一，不能靠大小写区分不同商品。
- 不把分类、价格、库存或促销状态编码进SKU。
- SKU不承担SEO职责，也不要求与商品Slug相同。
- 正式发布后原则上不改号；修改前检查订单历史、采购/库存对照、CSV和外部引用，并保存旧新映射。

### 商品与变体

- 简单商品：一个独立SKU。
- 可变商品：父商品保留SKU，每个可售变体另有唯一SKU。
- 变体后缀只使用已确认且有映射表的稳定属性代码，不直接拼接可能改名的显示值。
- 示例`TEST-DTL-ZR-0001`仅解释TEST格式，不代表正式SKU前缀、位数或品牌编码已确定。

## 品牌规则v1候选

- 使用正式公开英文名称，统一大小写、空格、标点和别名。
- 每个商品原则上只有一个主要品牌；制造商、经销商、自有品牌和OEM关系存在冲突时先由业务方说明。
- 品牌不建成Product Category、普通商品标签或Solutions。
- `Unknown`、文件夹名称和仓库分类不能成为正式品牌。
- 商城名称为`DentAll`，自有商品品牌为`ADS`；商城身份与商品品牌必须分开维护。
- ADS自有品牌商品前台品牌记录`ADS`；其他原厂商品仍记录包装上经确认的原厂品牌，例如`Aidite`。
- 实际工厂或供应商只有在它本身就是对外品牌时才进入品牌字段；制造商、供应商关系如需保存，应使用独立数据来源，不冒充商品品牌。
- D9记录品牌名称、来源、确认状态和负责人；D52再冻结品牌字段载体、归档URL、筛选和索引策略。
- 当前不自建品牌CPT，不安装品牌插件。

## Global Attributes规则v1候选

| 英文名称候选 | 主要用途 | Variation候选 | 关键边界 |
|---|---|---:|---|
| Material | 跨商品材质筛选 | 通常否 | 不复制为分类 |
| Size | 规格筛选和购买选择 | 是 | 产品规格，不是物流包装尺寸 |
| Shade | 牙科色号筛选和选择 | 是 | 与普通Color分开 |
| Color | 普通颜色筛选和选择 | 是 | 不承载牙科色号 |
| Package Quantity | 包装数量筛选和选择 | 是 | 不是库存数量 |
| Compatible System | 系统兼容性筛选 | 通常否 | 与Device边界待样本确认 |
| Compatible Device | 设备/手柄兼容性筛选 | 通常否 | 无法稳定区分时评估合并 |
| Intended Use | 跨分类用途筛选候选 | 通常否 | 无真实查找需求则不创建 |

属性只有在多个商品复用、需要筛选或形成购买选项时才创建为Global Attribute。单个商品的展示参数先用商品级属性或描述；原生字段不能满足且确有结构化展示价值时，才讨论最小ACF。

属性显示、筛选和Variation是三个独立开关。可筛选的材质或兼容系统不必生成变体；只有影响价格、SKU、库存、图片或实际购买选择的选项才进入Variation。

## 可复用核心思想

- WooCommerce建模的核心是职责单一：Product承载可售对象，Category负责浏览归类，Brand表示对外品牌，Attribute表达可比较规格，Variation表达真实可售组合，SKU标识具体库存单位。
- “可筛选”不等于“需要做变体”。只有影响购买选择、SKU、价格、库存、图片或可购买性的属性才应进入Variation，否则容易产生无意义的组合爆炸。
- SKU是稳定的业务身份证，不是商品名称、分类、URL或数据库ID。不要把价格、促销、分类等易变信息编码进SKU。
- WooCommerce原生提供SKU字段、搜索、导入导出和唯一性检查，但不提供完整的业务自动编号体系；先验证人工流程，再根据真实错误率决定是否开发生成器。
- 品牌、制造商、供应商和商城名称可能完全不同。商城是销售渠道，品牌是商品对外身份，供应商是采购来源，不能共用一个字段。
- 骨架应允许Website Manager自行新增商品、品牌、属性项和SKU；开发者只维护规则、权限和异常路径，避免成为内容生产瓶颈。
- 批量导入应先使用WooCommerce原生CSV和少量数据验证；只有稳定存在的格式转换、校验或幂等缺口，才值得开发自定义导入器。
