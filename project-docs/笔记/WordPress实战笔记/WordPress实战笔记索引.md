> 新建一篇Day学习笔记后，必须同时完成三件事：在本索引登记它；在学习笔记中链接对应的项目Day笔记；在项目Day笔记中反向链接该学习笔记。不能只依赖Obsidian自动生成的Backlinks面板。

> [!important] 默认收尾规则

| 笔记类型 | 回答的问题 | 应记录 | 不重复记录 |

## 使用方法

1. 自Day27起，每个Day收尾时复制[[WordPress实战学习笔记模板]]，命名为`Day{天数}-中文主题.md`，例如`Day27-Design-Token与Mobile-First容器.md`；不等到后续某天集中补写。
2. 填写YAML属性，并在“相关笔记”中链接本索引、当天项目笔记、直接相关的前后知识。
3. 回到当天项目笔记，在其“相关笔记”中补上新学习笔记，形成显式双向链接。
4. 只从当天真实实现中选择核心知识；先用实体比喻建立记忆宫殿，再用思维导图和准确技术映射纠正模型。
5. 阅读项目中的真实代码，完成一次可复演的观察、微型练习或排错，并回答5～7道费曼测试题。
6. 收尾时整理可复用结论、后续AI提问方式和跨项目变种；AI结论仍需用源码、官方资料或Local实验验证。
7. 在下表登记笔记与掌握度；后续理解变化时更新原笔记，不另造互相冲突的结论。

## 每篇学习笔记的固定骨架

1. 真实项目场景与最多3项学习成果。
2. 实体比喻（记忆宫殿）及逐项真实技术映射。
3. Obsidian可渲染的Mermaid思维导图与请求/生命周期调用链。
4. DentAll项目真实代码、文件职责、执行顺序和运行证据。
5. 安全、数据、SEO、缓存、交易、部署边界及排错练习。
6. 5～7道费曼测试题、掌握度与间隔复习记录。
7. 收尾总结、AI高效提问模板、其他项目的变种应用。

## Obsidian使用约定

- 链接正文使用`[[笔记名]]`或`[[路径/笔记名|显示名称]]`；同名文件出现歧义时写目录路径。
- 直接依赖必须显式互链；标签用于聚合，不能替代上下文链接。
- YAML中的`tags`保持少而稳定，建议使用`DentAll`、`WordPress实战`和一个主题标签。
- 可以使用Obsidian核心Templates插件插入模板；`{{date:YYYY-MM-DD}}`会生成当天日期，其余“待填写”字段需要手动替换。
- Callout、Mermaid和任务复选框均采用Obsidian原生支持的Markdown语法，不依赖Dataview等第三方插件。
- 不记录密码、Cookie、私钥、支付密钥、真实客户数据或无法公开的业务资料。

## 维护边界

- 自Day27起，每个Day默认生成一篇主学习笔记，并只提炼少量真正影响理解和排错的知识；多个紧密相关主题应组织成一条因果链，不为凑数量机械拆分，也不写没有真实项目依据的空教程。
- 比喻只帮助记忆，必须紧接真实技术映射，不能用比喻代替事实。
- “项目实战代码”必须来自当前仓库；若为便于教学而省略上下文，必须标注为“节选”或“简化示例”。
- 版本相关结论要注明验证环境；未经验证的推断标为“待验证”。
- AI回答不是验收证据；涉及版本、安全、数据或交易时，必须回到源码、官方资料或可复演测试核实。
- Shopify对照只用于迁移理解，不自动进入DentAll第一版实施范围；不确定的对应机制明确标为“待验证”。
- 学习笔记属于项目文档，可以提交Git；Obsidian工作区状态、缓存和个人插件配置不属于项目知识，不应提交。

## 可复用核心思想

- 跨平台不变量：有效学习不是收藏术语，而是建立“触发条件—执行机制—输出结果—验证方法—失败回滚”的因果链。
- WordPress/WooCommerce当前实现：用真实模板查找、Hook、enqueue、CRUD和请求生命周期解释项目代码，并在Local环境复演。
- Shopify或其他平台：主题模板、扩展点和资源管线名称会变化，但仍应寻找相同的职责边界；具体映射需按平台官方机制验证。
