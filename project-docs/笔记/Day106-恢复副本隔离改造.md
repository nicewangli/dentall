## 当前实施约束

- 目标保持 Access OFF；后续受控启动须保留已安装保护，并按新一轮实际测试用途核对入口、任务和外部副作用边界。
- Object Cache drop-in 早于 MU 插件加载，必须先在目标文件层处理；不得清空共享 Redis 或重启共享服务。
- 邮件拦截必须返回失败，不能伪报成功；DentAll Core 会根据成功发送事实更新报价订单。
- 阻止 Action Scheduler 执行须覆盖既有 runner 与异步入口，不能只改变新 Cron 排程频率。
- 备份配置应保存在目标 Web 根目录外的私有目录，密码不进入聊天或 Git；每步明确执行结果后再登记为已完成。

## 可复用核心思想

- 跨平台：恢复副本的数据库、运行入口和外部副作用需要分别检查；文件复制成功不能证明恢复可运行。
- WordPress/WooCommerce：先处理配置与早期缓存入口，再检查 MU 插件和任务执行。静态证据与运行证据应分开记录。
- 其他平台：对应控制取决于其环境变量、后台任务和外部连接机制；不能把 WordPress 的钩子当作通用网络隔离。
