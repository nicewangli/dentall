## 责任与发布边界

- Website Manager负责日常页面录入、维护，并按已批准来源核对业务事实；不能替业务负责人猜测或批准未知事实。
- 老板或指定业务/合规负责人负责联系方式、隐私、条款、配送、退货退款以及医疗、法规或承诺类正式内容确认。
- 当前团队没有独立SEO岗位。Website Manager按既有规则维护内容级Title、Meta Description和内链；已发布Slug、Canonical、robots、全局模板及技术SEO变更仍升级给开发者复核。
- 开发者负责Page模型、URL机制、菜单依赖、表单安全、SEO技术输出和系统一致性，不承担日常业务文案审批。
- 空白页、TEST页、缺负责人页和待业务确认页只能用于Staging结构验证，不得进入Production导航、Sitemap或正式内链。
- Contact的`product_id`只用于预填商品上下文；服务端必须重新读取商品，Canonical仍指向无参数基础URL。

## 可复用核心思想

- 跨平台不变量：页面清单、内容责任、URL、导航入口和发布状态应分开管理；“有一个页面”不等于“可以发布”或“可以进入导航”。
- WordPress实现：About、Contact和政策内容通常可以先用原生Page承载；WooCommerce的Cart、Checkout和My Account是功能绑定页面，不能仅按名称当作普通内容页处理。
- URL与治理：草稿和未公开TEST页面可以调整Slug，但进入菜单、Sitemap、内链或Production后，Slug就成为需要审计、重定向和回滚的公开资产。
- 内容治理：缺少正式业务事实时，先验证结构和流程，不用开发者推测的联系方式、政策或价格填充正式页面。
- Shopify对照：多数建站平台也区分页面内容、导航菜单和交易系统页面；具体页面模板、政策绑定和URL机制依平台实现，未在本项目中实测Shopify一一对应关系。
