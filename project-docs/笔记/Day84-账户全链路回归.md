# Day84：账户全链路回归

## 结论与范围

按用户已确认的B方案，在D83订单中心与D81/D82账户资料、默认地址增量之上，完成D84**非付款账户链**的隔离Local真实HTTP回归。订单归属、登录、资料、默认Billing/Shipping、旧订单快照、退出、找回及重置密码已串成同一TEST客户旅程。D83原生“再次购买”仍暂缓，D84的通过不表示该能力已恢复，也不表示支付、真实邮件或目标环境验收完成。

## 执行路径与技术取舍

环境为WordPress 7.1、WooCommerce 11.0.0、Storefront 4.6.2、PHP 8.2.29，DentAll子主题0.47.1、Core 0.7.1；独立TEST数据库的HPOS为off。浏览器走`http://127.0.0.1:18183`的真实HTTP和Cookie。登录、账户端点、表单Nonce、客户与订单持久化仍由WordPress/WooCommerce负责；`dentall-core/includes/customer-account.php`沿D79～D82既有Hook限制登录邮箱变更、保存前检查地址国家，并把找回公开结果归一、给重置密码增加12字符底线。D84只验证这些已确认能力之间的接力，没有把多个领域重写进同一模块。

TEST邮件在隔离副本由`pre_wp_mail`阻断，并且只把A的重置邮件捕获在Web根外的私有文件；未投递真实邮箱。副本还关闭对外HTTP、WP-Cron、Action Scheduler异步运行和支付网关，避免测试产生站外或交易副作用。旧订单地址通过订单对象快照核对，而不是用当前`WC_Customer`默认地址重新推算。

## 可复用核心思想

- 跨平台不变量：账户验收要串起匿名、登录、资料、地址、历史交易和凭据恢复，并分别比较“当前默认资料”与“历史订单快照”；单页通过不能证明全链一致。
- WordPress/WooCommerce当前实现：账户页与订单继续由原生端点、表单、Nonce及CRUD承载，DentAll Hook只补邮箱、国家和密码规则；重置密钥的生成、校验和用后失效由WordPress/WooCommerce承担。隔离Local的业务链可证明本环境行为，不能外推HPOS、目标缓存或真实SMTP。
- Shopify或其他平台：客户默认资料、订单快照和密码重置同样需要跨会话与跨角色验证；具体账户API、密钥与缓存机制待目标平台实测，不预设与WooCommerce一一对应。
