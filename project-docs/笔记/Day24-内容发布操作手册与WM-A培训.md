# DentAll 内容发布操作手册与 WM-A 培训

> 本手册用于 DentAll 第一版 WordPress 内容生产线。它说明如何安全创建、预览、送审、发布、更新、撤回和恢复 Post/Page，并把状态动作与素材授权写入项目 Markdown 登记簿。当前只适用于受保护 Staging；不得把 TEST 对象、示例政策或未授权素材当成正式内容发布。

## 1. 工作时必须理解的四条底线

1. **标题含 TEST 的对象只能用于 Staging 验证。** 未经业务确认的工厂数据、资质、材料、产能、交付、价格、政策和法律声明必须保持 Draft 或 Pending Review。
2. **Published 对象点击“更新”会直接改变公开内容。** 高风险改写不能直接写入公开源对象，必须先建立独立审阅 Draft。
3. **改回 Draft 不等于已经下线。** 还要检查精确原 URL、Sitemap、导航和缓存；旧正文仍以 HTTP 200 返回时属于 P0。
4. **素材可上传不等于可发布。** 来源、授权、允许渠道/地区、修改权、署名、有效期和批准人没有证据时，只能登记为待核验或开发占位。

## 2. 当前角色与责任

### 2.1 WM-A 可以做什么

- 创建和编辑文章、页面及媒体元数据。
- 保存 Draft、设置 Pending Review、在完成检查后发布或撤回内容。
- 维护摘要、分类、标签、特色图、正文图片、内链和 Yoast 内容级字段。
- 在 `project-docs/CONTENT_ASSET_REGISTER.md` 中登记发布/变更动作和素材授权事实。

### 2.2 WM-A 不应做什么

- 不进入用户、插件、主题、工具和 WordPress 全局设置；直接访问相应后台入口也应被拒绝。
- 不安装插件、不修改主题/代码、不改 Reading、固定链接、全局 SEO、Canonical 或 robots。
- 不把 Administrator、历史测试账号、共享账号或虚构邮箱当成第二位 Website Manager。
- 不替业务负责人确认正式政策、法律/医疗/合规声明或素材权利。

### 2.3 第一版审核边界

- 当前只使用 WM-A。`Pending Review` 是协作信号，不是系统强制审批闸门；WM-A 仍具备发布能力。
- WM-B 已按 CR-007 从 D24-D25 当前范围排除。第二人正式上岗、出现角色差异、强制互审、交接、并发登记或审计需求时，再用公司控制的独立邮箱建立账号并专项补验。

## 3. Post 与 Page 字段不要混用

| 项目 | Post（文章） | Page（固定页面） |
|---|---|---|
| 主要用途 | 博客、工厂/公司/产品与服务内容 | About、Contact、政策、Solutions 等长期页面 |
| 分类与标签 | 有；分类是主组织维度，标签可选 | 原生 Page 无分类和标签 |
| 摘要 | 代表样本和正式送审文章应填写 | 原生 Page 通常不使用摘要 |
| 父级与模板 | 通常不使用父级 | 可设置父页面和页面模板 |
| 博客列表 | 可能显示标题、特色图和摘要 | 不进入博客列表 |
| 正文标题 | 标题由模板输出唯一 H1；正文从 Paragraph/H2 开始 | 同样由标题输出唯一 H1；正文不要再插入 H1 |

第一版 Solutions 采用原生 Page 优先，不注册重复 CPT。只有未来出现大量独立条目、独立归档/详情或筛选需求时，才重新评估 CPT。

## 4. 新内容的标准操作路径

### 4.1 创建与保存 Draft

1. 进入“文章 → 写文章”或“页面 → 添加页面”。
2. 输入明确标题；TEST 对象必须在标题和首段标明 `TEST` 或 `TEST REVIEW COPY — DO NOT PUBLISH`。
3. 正文使用 Paragraph、H2/H3、List、Image 等允许区块；不得插入第二个 H1，不用空行、Spacer 或行内样式排版。
4. 点击“保存草稿”，再从右侧文档面板回读状态、Slug、作者、评论和适用字段。
5. 首次公开前可以修正未公开 TEST Slug；对象一旦公开过，Slug 变更必须走 URL/SEO 变更记录。

### 4.2 Post 自检

- 摘要是 1-2 句独立概括，不机械复制正文首段。
- 正式送审至少有一个正式主分类；不得用 `Uncategorized`、TEST 或空分类冒充正式分类。
- 标签可为空；使用时必须可被多篇文章复用且不与分类重复。
- 特色图送审基线为 16:9，推荐 1600×900；文件名、尺寸、压缩、授权和 alt 都要检查。
- 有真实相关目标时使用描述性锚文本添加内链；不得链接 `wp-admin`、预览 URL 或临时 Staging 专属地址。

### 4.3 Page 自检

- 核对标题、Slug、作者、模板、父级、评论和状态。
- 政策 Page 的期限、适用条件、例外、费用、退款时间、地址和联系信息必须有业务/法律确认；示例模板文字不能当成批准政策。
- 不为凑样本重复创建 Privacy、Refund 或 Solutions Page，也不擅自改现有系统绑定。

### 4.4 预览与匿名隔离

1. 用登录态预览检查唯一 H1、H2/H3 顺序、列表、图片、链接和内容结构。
2. 用未登录/无痕窗口访问不带 `preview=true` 的精确 URL 或 `?p={ID}` / `?page_id={ID}`。
3. Draft/Pending Review 应返回 404 或其他明确不可见状态，且正文不得泄露。
4. 在对应 Sitemap 中搜索 Slug；Draft/Pending Review 不得出现。
5. 检查 Primary/Handheld 导航没有自动加入未批准 Page。

## 5. 高风险 Published 更新：独立审阅 Draft

下列任一情况属于高风险：大幅改写、业务/医疗/法规/安全声明、资质/产能/交付承诺、素材授权、已发布 Slug、Canonical、robots 或索引策略。

### 5.1 完整路径

1. 记录公开源对象 ID、精确 URL、当前状态、原内容和变更原因。
2. 新建标题明确标识的独立审阅 Draft，不直接修改 Published 源对象。
3. 在审阅 Draft 中完成正文、摘要、分类/标签、媒体、内链和 Yoast 内容级字段。
4. 登录态预览；匿名精确 URL 和 `?p={ID}` 必须 404，且不进入 Sitemap、导航或正式内链。
5. 在 Markdown 登记簿中登记变更范围、复核人、必要业务确认人、证据和恢复方案。
6. 只有取得真实批准后，才把批准内容同步到 Published 源对象；同步后立即复核精确 URL、缓存、Sitemap、导航和 SEO 输出。
7. 审阅 Draft 按登记方案继续保留或清理，并记录最终结果。

> WordPress 原生修订不能在同一 Published 对象上保留“旧版在线、新版待审”的真正待审修订。若未来需要该能力或强制职责分离，必须另登记范围并评估工作流方案。

## 6. Yoast 内容级 SEO 操作边界

WM-A 可维护：

- Focus keyphrase（用于编辑提示，不是排名保证）。
- SEO Title。
- Meta Description。
- 普通内容的标题、摘要、正文、内链和图片 alt。

WM-A 不自行更改：

- 已公开 Slug、Canonical、robots、索引状态和全局 Title/Schema 模板。
- 作者 Schema、站点级 Sitemap、固定链接或 Production SEO 设置。

评分颜色不是发布门槛。内容准确、权限、授权、URL、索引与可回滚性优先于把 Yoast 指示灯调成绿色。

## 7. 图片与素材授权

### 7.1 上传前

- 确认文件来源和权利人。
- 确认授权证据位置、渠道/地区、是否允许修改、署名要求、有效期和批准人。
- 特色图采用 16:9 基线；正文图可保留合适真实比例，但要控制尺寸、压缩和布局稳定性。
- 文件名使用简短英文小写和短横线；alt 描述当前语境中的图像用途，不堆砌关键词。

### 7.2 上传后

- 在媒体详情核对像素尺寸、文件名、alt 和附件 ID。
- 把附件 ID、使用对象、公开路径、发布状态及撤回/替换方案写入“素材授权登记”。
- 没有真实授权证据时，不得把 TEST 模板或口头推测改成“允许公开”。

### 7.3 D24 已发现的边界

- 竖版 TEST 图可以验证特色图机制，但不符合正式 16:9 基线；已从 A/C5 样本中移除。
- 长文正文 TEST 图可继续用于受保护 Staging 的机制验证；没有正式授权前，不能写成真实素材样本通过。

## 8. 修订、回收站与撤回

### 8.1 原生修订能恢复什么

- 主要覆盖 Post/Page 的标题、正文、摘要等受支持内容字段，并记录对应修改账号和时间。
- 不应假定分类/标签、特色图、媒体元数据、作者、状态和 Yoast 字段能随修订完整恢复。

### 8.2 两种恢复必须区分

- “页面/文章 → 回收站 → 恢复”：D24 实测从 Published 移入回收站后，普通恢复得到 Draft，不会自动重新公开。
- 移入回收站后的页面提示“撤销”：D24 实测会恢复移入前的 Published 状态并立即重新公开。它不是普通安全恢复的同义词。

### 8.3 撤回后的四链检查

1. 后台状态为 Draft/Private/Trash。
2. 对应 Sitemap 不再包含 Slug。
3. Primary/Handheld 导航和其他正式入口不再包含对象。
4. 清理 Breeze 及适用的 Varnish 后，用**不带随机参数的精确原 URL**复测，应为 404/批准的不可见状态且无旧正文。

随机查询参数只能辅助判断缓存，不能替代精确原 URL。安全的 404 后续被缓存为 `X-Cache: HIT` 不等于泄露；旧 Published 正文仍以 200 返回才是失败。

## 9. Markdown 登记簿怎么填

当前唯一活动登记文件：`project-docs/CONTENT_ASSET_REGISTER.md`。历史 `.xlsx` 中的 D24 A/C3-A/C4 记录已迁移，生成文件已删除且不入库，也不得重新生成作为第二事实来源。

### 9.1 内容发布与变更登记

每个状态动作至少填写：

- 记录 ID、环境、对象类型、对象 ID、标题、精确 URL/预览 URL。
- 动作类型、变更摘要、变更前/后状态。
- 执行人、复核人、必要业务确认人。
- 依据/证据位置、操作时间、撤回/恢复方案、验证结果和备注。

发布、更新、撤回、移入回收站、恢复、缓存清理和高风险同步都要建立独立Markdown记录。不能从 `post_author` 或修订记录反推这些状态动作。

### 9.2 素材授权登记

只登记真实、可追溯事实。登记簿中的 `AST-XXX` 只是空白字段模板，不是授权证据；首次正式使用时必须用真实资产ID和证据完整填写，不能把模板状态改写成“批准公开”。

### 9.3 文件治理

- 活动登记只维护 Git 仓库中的上述 Markdown 文件；不要另建 Excel、Google 表格、邮件附件或桌面副本作为第二份主记录。
- 本手册只维护当前 Markdown 源文件；不再生成或维护 Word、Excel、Google 表格等并行版本。需要阅读、打印或培训时直接使用 Markdown，避免多份内容分叉。
- 当前由项目负责人/WM-A维护业务事实，Codex按已提供证据整理结构；提交历史提供版本追踪，但不能替代业务批准证据。
- 公司控制的 Git 远程归属、备份和交接责任必须在 D25 开放批量录入前确认。WM-B 当前不参与；未来多人协作时再专项验证分支、合并冲突和责任归属。

## 12. P0/P1 停止条件与回滚

### 12.1 P0：立即停止并先恢复安全状态

- Draft/Pending/审阅副本匿名可见、进入 Sitemap/导航，或正文通过匿名 REST 泄露。

### 12.2 P1：关闭前不得判样本通过

- 必要字段无法保存或重开回读。

- 修订恢复错误版本/状态，或把分类、特色图和 Yoast 误认为会随修订恢复。
- 后台状态、精确 URL、Sitemap、导航或缓存持续不一致。

## 可复用核心思想

- **跨平台不变量：** 内容字段、公开状态、审核责任、素材权利、URL/索引和审计记录是不同层级；任何 CMS 都不能用“后台显示已保存”替代公开面和证据链验证。
- **WordPress/WooCommerce 当前实现：** `Pending Review`不是强制审批；Published“更新”和修订恢复会直接改变公开对象；普通回收站恢复与提示条“立即撤销”可能得到不同状态；撤回还受页面缓存影响。
- **Shopify或其他平台对照：** 同样需要草稿/发布权限、素材授权、URL重定向、主题导航和变更留痕，但审核、版本和恢复机制依平台能力而异；未实测前不得把 WordPress 行为当成一一对应的行业默认。
- **培训原则：** 真正的人员验收不是背编号或闭卷复述，而是能使用受控 SOP 识别风险、选择正确分支、验证公开面、留下可追溯记录，并在不确定时停手升级。
