# Day103：权限与账户暴露审计

## 结论与范围

D103 对照总计划“权限和账号审计、编辑/客户越权测试、权限基线完成”开展检查。首轮发现并收紧Users REST的后台作者资料读取；2026-10-08又补齐整合分支Customer Cookie＋Nonce真实请求证据。2026-10-17按A包及Blog链接确认，在Core 0.9.2候选中收口Post的oEmbed/Feed自动作者输出，隔离验证通过，详见下方续作记录。该身份展示问题不等于登录凭据泄漏；作者Feed既有self路由、正文人工文本、非Post和目标缓存仍各有边界。RSK-057/P2目标环境未闭环，RSK-061/P1旧SSH授权仍待处置，D103不标记Done。

## 可复用核心思想

- 跨平台不变量：公开署名、后台身份和登录凭据是三种不同事实。收紧一个 API 后必须枚举 HTML、嵌入、Feed、缓存与第三方输出，才能判断整个身份暴露是否关闭。
- WordPress/WooCommerce当前实现：站点级 Users REST 读边界可通过 `rest_request_before_callbacks` 定向拦截；路由大小写、请求参数覆盖与内部嵌入派发必须纳入真实 REST 测试；保留文章作者数字关联和原生权限。
- Shopify或其他平台：同样要核定员工身份、内容作者和公开资料的授权边界；具体 API、主题与 Feed 输出机制需按目标平台官方资料与实测确认，待验证。
