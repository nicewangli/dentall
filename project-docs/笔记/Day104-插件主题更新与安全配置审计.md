# Day104：插件主题更新与安全配置审计

## 结论与范围

D104 对照总计划中的插件主题更新审计、安全配置和敏感信息检查推进。2026-10-07 的 Staging 盘点记录为 WordPress 7.1.3、WooCommerce 11.0.0、Breeze 2.5.12；本轮核定的官方更新目标分别为 WooCommerce 11.2.0 与 Breeze 2.6.1。旧版本低于已发布的安全修复版本，但版本落后本身不能证明 DentAll 已被利用或具备公告中的全部触发条件。全新 TEST 隔离站已完成 WooCommerce 受控升级、数据库迁移、Breeze 目标版新装冒烟、定向回归和配对恢复；隔离站没有 Staging 的 Breeze 2.5.12 配置，不能复演其原位升级。**共享 Staging、Production 尚未升级，D104 安全基线未验收**。

## 授权与职责边界

用户已同意按本轮方案实施受控升级检查与隔离演练。此授权覆盖隔离副本中的版本更新、必要数据库迁移、定向回归与恢复验证；不把共享 Local、Staging、Production、真实付款、邮件、DNS 或缓存策略纳入自动操作范围。开发者负责版本、依赖、数据库、扩展点与回滚证据；业务人员只在后续目标环境窗口参与内容与核心购物流程验收，不代替技术验证。

## 最多3项验收结果

1. 插件、主题、核心的现有版本、官方更新目标和变更风险均有可核对来源。
2. 独立隔离站完成 WooCommerce 升级与数据库迁移、Breeze 2.6.1 启用冒烟，关键商城、账户、REST 与可观察缓存边界通过定向验证；不把隔离结果外推为 Staging 的 Breeze 原位升级或缓存配置通过。
3. 从升级前同一时点的文件和数据库快照恢复，并记录结果；Staging 的真实插件、主机缓存与发布窗口另行验收。

当前第1项已完成版本与公告核对；第2项中的 Woo 更新组、Breeze 新装生命周期、plain query REST、商品和 Cart 子面已有隔离证据，Checkout 在 TEST 配置下重定向 Cart，账户/PayPal/Yoast 与目标缓存未验；第3项的 TEST 配对恢复通过。D104 的“安全基线完成”仍未达成，RSK-058/P2 保持开放。

## 安全配置与敏感信息

- 当前 Git 跟踪范围排除 `wp-config.php`、数据库、上传媒体、日志与常见凭据文件；本轮仅有范围有限的仓库扫描，不能把“没有命中已扫描模式”写成全历史无泄漏证明。
- Staging 的密码保护、`noindex`、缓存层与访问日志等必须在发布窗口读取实时配置；历史记录不能替代 2026-10-08 的现场结果。数据库快照和文件包可能含账号、配置或 TEST 邮件信息，应限制在隔离目录和受控访问范围内，不进入 Git。
- 升级涉及 WooCommerce 订单、HPOS、Action Scheduler、Cart/Checkout 与 PayPal Sandbox 的兼容面；当前不发真实邮件、不产生真实支付，也不修改正式订单。

## 回归与发布闸门

升级前先核对目标环境的核心、主题、插件、PHP、数据库与活动组件，尤其确认 PayPal Payments、Yoast、Breeze、Storefront 和第一方版本；保留同一时点的代码、数据库、`uploads` 和配置备份及独立恢复路径。发布窗口还要确认无在途付款、待执行邮件或报价竞态，必要时按已有发布规程限制交易。升级后核对 WooCommerce 数据库迁移、HPOS 与 Action Scheduler 状态，复测商品/变体、购物车、Checkout、My Account、REST、邮件模板、PayPal Sandbox、SEO 输出和错误日志。Header 中的 `WC tested up to` 较旧只表示所声明的测试上限，不等于已证实不兼容；需以供应商公告和代表场景实测判断。

Breeze 必须在 Cloudways 的真实页面缓存、Varnish 与对象缓存组合下复验公开页 HIT/MISS、登录态与交易页隔离、撤稿后的旧缓存清除、REST 响应及资源加载。TEST 的自动 Page ID 排除只证明此新装配置，Staging 手工项为空时仍要查最终生成配置及代理规则。隔离站的功能性通过只允许推进到目标环境受控窗口，不能直接关闭缓存风险。发现数据库迁移失败、交易金额/归属异常、受保护响应被缓存或 P0/P1 时停止发布并按同一快照恢复；不能仅降回旧 WooCommerce 文件。

## 可复用核心思想

- 跨平台不变量：依赖更新常改变代码、持久数据与缓存契约。只有同一时点的完整备份、真实迁移结果、关键流程验证和配对恢复，才支撑可回滚的发布判断。
- WordPress/WooCommerce当前实现：WooCommerce 插件版本与数据库版本是两个检查点；Breeze 的 PHP 页面缓存、Cloudways Varnish 和对象缓存是不同层。更新后必须在目标组合中分别检验交易隔离和旧缓存撤销。
- Shopify或其他平台：也需要核对扩展版本、数据迁移、边缘缓存及恢复能力；具体发布和回退机制应查目标平台官方资料并实测，待验证。
