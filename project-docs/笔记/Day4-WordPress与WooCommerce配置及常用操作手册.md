## Slug、页面标题和页面绑定

- **Slug（别名）** 是网址中域名后面的路径片段，例如 `/cart/` 中的 `cart`。
- 页面标题可以显示为英文，中文后台菜单只影响管理员界面语言。
- 页面存在不代表 WooCommerce 已绑定；必须同时检查 WooCommerce 页面设置。

| 用途 | 页面标题 | Slug | 检查位置 |
|---|---|---|---|
| 商店 | Shop | `shop` | 页面列表及 WooCommerce 商品设置 |
| 购物车 | Cart | `cart` | WooCommerce → 设置 → 高级 → 页面设置 |
| 结账 | Checkout | `checkout` | WooCommerce → 设置 → 高级 → 页面设置 |
| 我的账户 | My account | `my-account` | WooCommerce → 设置 → 高级 → 页面设置 |
| 条款和条件 | 后续创建 | 待定 | 当前可留空，上线前补齐并绑定 |

## 最常用操作

### 修改自己的后台语言

1. **用户 → 个人资料**。
2. 修改“语言”。
3. 更新个人资料。
4. 这只影响当前用户的后台界面，不会自动把第一版英文前台改成中文。

### 检查运行环境版本

1. **工具 → 站点健康 → 信息**。
2. 展开“服务器”查看 PHP 版本。
3. 展开“数据库”查看数据库版本。
4. 展开“WordPress 常量”和文件权限时，不要公开包含路径或敏感信息的完整截图。

### 检查 WooCommerce 版本

1. **插件 → 已安装插件**。
2. 找到 WooCommerce。
3. 查看版本、启用状态和更新提示。
4. 更新前核对兼容性并创建即时备份。

### 检查页面绑定

1. **WooCommerce → 设置 → 高级**。
2. 在“页面设置”核对 Cart、Checkout 和 My account。
3. 条款页面当前允许留空，上线前必须补齐。
4. 页面列表中同时确认页面已发布、Slug 正确且不存在重复页面。

### 检查固定链接

1. **设置 → 固定链接**。
2. 文章选择“文章名”。
3. 商品链接结果保持 `/shop/商品别名/`。
4. 如果保存后选中“自定义基础链接”，但输入值是 `/shop/`，最终 URL 仍然正确。

### 检查支付是否关闭

1. **WooCommerce → 设置 → 付款**。
2. 检查所有线上和线下方式的启用状态。
3. 插件列表同时确认 WooPayments、PayPal 等支付插件是否安装。
4. D4 阶段不输入真实商户密钥、不启用真实支付。

### 查看后台计划任务

1. **工具 → 计划操作**，或 **WooCommerce → 状态 → 计划操作**。
2. 重点查看失败、超时和长时间待处理任务。
3. Action Scheduler 是 WooCommerce 及插件执行异步任务的队列，不等同于 Cloudways 的系统 Cron 页面。
4. 未理解任务来源前不要批量取消或删除。

### 排查插件是否真的安装

1. 先看 **插件 → 已安装插件**。
2. 若后台列表没有，再用 SFTP 查看 `public_html/wp-content/plugins/插件目录名/`。
3. 只有目录存在不代表插件已启用；只有后台启用也必须以实际功能测试为准。
4. 本次 Cloudways 初始应用没有 WooCommerce 目录，因项目从零开始，已从官方插件库重新安装 11.0.0。

## 常见故障与检查位置

| 现象 | 第一检查位置 | 判断方法 |
|---|---|---|
| 后台突然变英文 | 用户 → 个人资料 | 检查当前用户语言，不要先改全站语言 |
| 页面存在但购物车/结账不工作 | WooCommerce → 设置 → 高级 | 核对页面绑定、发布状态和 Slug |
| 商品网址不正确 | 设置 → 固定链接 | 核对文章名与商品 `/shop/` 基础结构 |
| WooCommerce 功能不见了 | 插件 → 已安装插件 | 检查插件是否存在和启用，再检查 SFTP 目录 |
| 支付选项不见或不可用 | WooCommerce → 设置 → 付款、插件 | 检查对应网关插件、国家和账户配置 |
| 邮件显示发送但客户没收到 | WooCommerce → 状态 → 日志、Cloudways SMTP | 核对 SMTP、发件域名和邮件日志 |
| 后台任务积压 | 工具 → 计划操作 | 查看失败任务的 Hook、日志和来源插件 |
| 修改后页面仍旧 | 保存状态、Cloudways 缓存 | 先确认保存，再清缓存；不要反复改配置 |
| 出现数据库连接错误 | Cloudways 服务和数据库凭据 | 停止继续修改，检查数据库服务与最近凭据变更 |
| 插件更新后报错 | WooCommerce → 状态 → 日志、站点健康 | 使用更新前恢复点或回滚方案，不修改插件核心 |

## 安全与范围禁区

- 不修改 WordPress、WooCommerce、父主题或第三方插件核心文件。
- 不把 PHP、CSS、JS 长期放在后台代码框或页面编辑器中。
- 未经确认不启用真实支付、不修改 DNS、不关闭 Staging 的 noindex。
- 不删除 Cart、Checkout、My account 等核心页面。
- 不随意修改已有 Slug、固定链接、商品分类基础地址；这些会影响 URL 与 SEO。
- 商品使用 WooCommerce 原生 Product；筛选规格使用全局 Attributes；价格或库存差异使用 Variations。
- 管理员、访问保护、数据库、Redis、SMTP 和支付密钥均不得写入文档或 Git。

## 可复用核心思想

- WordPress中的“页面标题”“Slug”“固定链接规则”和“WooCommerce功能页绑定”是不同层次，修改任何一层都要检查URL与业务流程。
- WooCommerce核心页面不能仅凭页面可打开就判定正常，还要验证Shop、Cart、Checkout和My Account的绑定与状态跳转。
- 配置工作应保留四项证据：修改前值、修改后值、验证页面或命令、回滚方法。
- 暂未确认的支付、税费和配送规则应保持关闭或TEST状态；空配置通常比错误的临时业务配置更安全。
- 插件显示“已上传”不代表已安装、已启用或已完成数据库升级，必须分别核实生命周期状态。
- Slug和固定链接一旦公开就成为SEO资产；随意改名不仅是后台操作，还可能需要重定向、Canonical和索引检查。
