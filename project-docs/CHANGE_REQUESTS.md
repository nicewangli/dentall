# 需求变更登记

## 使用规则

- 所有新增、修改、删除需求先登记，再进入开发。
- 需求未明确验收标准或影响时，状态为`Needs clarification`。
- 影响数据库、URL、支付、权限、SEO、缓存或生产环境的变更必须包含回滚方案。
- 未经确认，不将新增需求免费吸收进原工期。

## 状态

`Inbox → Needs clarification → Ready → In progress → Review → Staging → Awaiting approval → Done`

### CR-004：条件询价后人工建单付款流程

- 类型：新增并细化原询价范围。
- 提出日期：2026-08-14。
- 优先级：P1。
- 状态：Needs clarification；当前不进入实施，只有出现真实询价商品时重新评估。
- 原约定范围：第一版测量要求已包含询价开始与提交事件，但商品展示、询价记录、报价确认和转订单流程尚未明确。
- 最新业务确认：老板要求以标准价格商品为开发核心，少量定制商品通常只作展示；第一版暂不要求询价表单、邮件报价或人工报价转订单。
- 条件需求：若以后确认真实询价商品，则继续使用普通Product详情页，通过显式销售模式显示`Request a Quote`；提交保存后台记录并发送邮件通知；人工确认后由授权订单人员创建WooCommerce待付款订单并发送付款链接。
- 业务原因和用户价值：保持标准商品的普通购物车闭环，同时避免未定价定制商品以错误金额进入购物车；报价确认后复用WooCommerce订单、支付和发货能力。
- 影响页面/模块：商品列表状态、商品详情购买区、询价表单与结果状态、后台询价记录、邮件通知、人工订单及付款链接、GA4询价事件。
- 影响文件/数据：未来新增显式销售模式和询价记录；不创建重复商品Page或CPT，不修改已成交订单。
- URL/SEO影响：商品继续使用唯一Product URL；共用询价表单页如存在，应避免成为重复商品详情或索引入口。
- 权限/安全影响：表单需防垃圾、nonce、清洗、验证、转义和个人信息保护；原方案要求单独授权订单人员，后续Website Manager已按CR-006/ADR-015获得订单能力，但真实询价转订单仍需操作流程和审计。
- 支付/物流/缓存影响：询价阶段不进入购物车、支付、库存扣减或`purchase`事件；报价确认后的待付款订单必须包含最终商品金额和运费，并按动态页面规则排除缓存。
- 预计工时：当前0天实施；若重新启用，乐观2天 / 可能3天 / 保守4天，不含附件上传、Quote Basket、在线议价、PDF报价、CRM同步和自定义订单状态。
- 进度影响：当前不占第一版开发工时；释放时间回到标准价格、库存、购物车、结账、支付、物流和回归。未来重新启用时必须重新排期，不占用这些不可压缩工作。
- 新风险：邮件丢失、垃圾提交、个人信息暴露、错误价格或运费进入订单、未授权人员访问订单、询价事件误报为购买。
- 回滚方式：停用询价入口并保留既有记录导出；标准商品购物车不依赖询价模块，回滚不得删除已创建订单或客户提交记录。
- 验收标准：四端询价入口和表单状态可用；提交同时产生后台记录和通知；重复/垃圾/失败路径可处理；报价后可创建正确金额与运费的待付款订单并发送付款链接；付款后订单、邮件和发货状态正确；询价不误触发`add_to_cart`、`begin_checkout`或`purchase`。
- 需要谁确认：重新启用前，由业务方提供真实询价商品、处理人员、收件邮箱、隐私文案和SMTP要求。
- 对应任务、提交和截图：D10规则、ADR-013历史方案、ADR-014当前方案；实现阶段回填。

- 新需求：定制展示商品显示经业务确认的参考价格范围，并提供`Contact Us About This Product`；复用D89联系表单，通过Product ID安全携带商品上下文，不建设独立询价系统。
- 业务原因和用户价值：让客户理解定制服务的大致预算并能准确说明咨询对象，同时保持第一版以标准价格商品交易闭环为核心。
- 影响页面/模块：商品卡价格状态、商品详情展示购买区、Contact表单商品上下文、邮件内容和联系表单事件参数。

- URL/SEO影响：商品继续使用唯一Product URL；`/contact-us/?product_id={ID}`只用于预填上下文，Canonical保持`/contact-us/`，不得产生可索引的重复联系页；参考范围不输出为可购买Offer。
- 权限/安全影响：服务端校验Product ID并重新读取商品，不信任查询参数中的名称或金额；沿用联系表单nonce、清洗、验证、转义、反垃圾、隐私和邮件失败处理。

- 预计工时：乐观0.5天 / 可能0.75天 / 保守1天；不含通用Contact表单本身、独立询价系统、文件上传或报价转订单。
- 进度影响：参考价格字段随商品模型验证；前台展示购买区随商品详情实现；商品上下文传递并入D89 Contact开发，不改变D120总里程碑，若超出优先削减P3增强。
- 新风险：参考范围被误认为固定报价、URL参数被篡改、联系邮件缺失商品上下文、错误输出Offer Schema。
- 回滚方式：停用展示价格范围和商品上下文预填，保留普通Contact页面；不影响标准商品购物车和历史订单。
- 验收标准：四端正确显示参考范围和免责声明；无价格时有可接受状态；无法直接加购；Contact页显示并提交正确商品；篡改或无效Product ID被安全忽略；联系表单成功/错误/邮件失败可验证；无误导性Offer Schema。
- 需要谁确认：方案已确认；正式参考范围、按钮英文文案、联系收件人和隐私文案在实现前由业务方确认。
- 对应任务、提交和截图：ADR-014、D10规则；实现阶段回填。

### CR-006：Website Manager扩展为商城运营负责人

- 类型：修改。
- 提出日期：2026-08-15。
- 优先级：P1。
- 状态：In progress；Local代码、账号与第一轮权限走查已完成，等待Staging部署和冒烟。
- 原约定范围：Website Manager只管理商品与内容，不处理订单、优惠券、客户、WooCommerce设置、支付、税费、物流或高影响删除。
- 新需求：Website Manager获得WordPress文章、页面、媒体、分类、标签和评论的完整业务内容能力，以及WooCommerce完整商品、`shop_order`、`shop_coupon`能力、`manage_woocommerce`、`view_woocommerce_reports`、`create_customers`和`delete_product_terms`；允许业务内容、商品、订单、优惠券和商品术语的批量及永久删除。
- 业务原因和用户价值：由一个业务负责人账号完成商城日常运营，减少开发者代操作和角色切换。
- 影响页面/模块：文章、页面、媒体附件元数据、分类、标签、评论/商品评价、内容级SEO、商品、属性、Shipping Class、订单、优惠券、客户创建、报表、WooCommerce设置/状态、支付网关和Webhooks。
- 影响文件/数据：`dentall-core`角色白名单及版本化同步；Local与Staging分别建立独立测试账号；客户创建会写入WordPress用户表。
- URL/SEO影响：删除商品、分类、属性或Slug会产生失效URL、归档变化和SEO风险；能力开放不代表可跳过批量删除与URL变更评估。
- 权限/安全影响：仍不授予`manage_options`、用户管理、插件、主题、核心更新、数据库和部署权限；Website Manager可管理文章评论和商品评价；媒体格式和5MB边界保留。
- 支付/物流/缓存影响：`manage_woocommerce`可修改支付、税费、物流、邮件和Webhooks；订单操作可能触发库存回补、退款和邮件。D12验收只读检查高影响设置，禁止真实支付、真实退款和外发邮件。
- 预计工时：乐观0.5天 / 可能0.75天 / 保守1天，用于代码、安全审查、Local/Staging账号及权限矩阵；不含正式支付、物流和生产审计。
- 进度影响：优先使用D12～D18原权限验收预算；若Staging或交易副作用出现P1，不压缩支付、库存、订单和上线回归，顺延低优先增强。
- 新风险：误删商品/术语/订单、改变全局商城设置、Webhook数据外发、支付或退款误操作，以及多人共享高权限账号。
- 回滚方式：将角色白名单恢复到内容负责人边界并提升角色版本；保留操作审计和数据备份，已删除数据按备份/回收站策略恢复，不直接覆盖订单数据库。
- 验收标准：Local与Staging各有独立Website Manager操作账号；文章、页面、媒体元数据、评论/商品评价与商城允许项真实可用；WordPress用户、插件、主题和系统直链拒绝；媒体格式/大小边界有效；支付、退款、邮件和正式数据未触发。
- 需要谁确认：权限范围已由用户确认；Production启用前需再次确认具体人员、MFA、审计、备份和支付/退款职责。
- 对应任务、提交和截图：D12 C1～C3、ADR-015；Staging证据在后续周期回填。
